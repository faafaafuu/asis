# Модуль «Магазины»

Ищет продукты в магазинах, сравнивает цены и держит список покупок.
Голосом: «Ноа, найди молоко в магазинах», «добавь молоко в список», «что в списке».

## Откуда он взялся

Тем же самым занималась отдельная служба FoodPilot: NestJS, PostgreSQL, Redis и
Docker. Поиск при этом состоит из двух запросов в интернет и разбора ответа —
базы он не требовал никогда. Пока служба не была запущена, Ноа на просьбу найти
продукты отвечала «поиск по магазинам не отвечает», а запустить её значило
поставить Docker и поднять две базы. Здесь то же самое — модулем.

| Магазин | Как спрашиваем |
|---|---|
| Магнит | данные страницы поиска (`__NUXT_DATA__`) |
| Метро | состояние страницы (`window.__NUXT__`), считается в песочнице `node:vm` |
| ВкусВилл | разметка страницы поиска |
| Пятёрочка | parse.bot по ключу пользователя — сама она программам отвечает 403 |

Магазин, который не ответил, минуту не тревожим: список покупок — это несколько
поисков подряд, и лежачий магазин не должен стоить ожидания на каждом товаре.

## База

Файл `shops.json` рядом с модулем: список покупок и выбранный магазин. Пишется
через временный файл с переименованием, чтобы выключение света посреди записи не
оставило половину списка.

## Чего здесь нет

Оплаты и оформления заказа. Модуль доводит до списка с ценами и ссылками —
дальше человек нажимает «купить» сам. Для оплаты по-прежнему нужна служба
заказов.
